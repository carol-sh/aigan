# v4 검토: 인간-LLM 관계를 뒤집으면

보통은 사람이 LLM을 도구로 쓴다. 이 문서는 그 관계를 뒤집어 본다. 에이전트가 사람을 도구로 쓸 때, 일반 사용자가 LLM으로 하는 일들이 v4 모델(방침 → 목표 → 흐름)로 표현되는지 확인한다. 개발자 용도는 제외한다.

## 사람들은 LLM으로 무엇을 하나

| 출처 | 요지 |
|---|---|
| OpenAI·NBER "How People Use ChatGPT"(2025.9) | 실용 안내(튜터링, 방법, 조언), 정보 찾기, 글쓰기가 대화의 약 80%. 실용 안내가 약 28%로 가장 크다. 업무 외 사용이 70% 이상. 글쓰기는 새로 쓰기보다 사용자 글을 고치는 일이 많다. 그 밖에 기술 도움, 멀티미디어, 자기표현(잡담, 관계, 롤플레이) |
| Anthropic Economic Index | 코딩이 가장 크다(약 1/3). 나머지는 글쓰기, 분석, 교육 순. 위임(automation)과 협업(augmentation)이 반반 |

이 검토에서는 개발을 빼고 범주를 일곱 개로 나눈다: 정보 찾기, 실용 안내, 글쓰기·편집, 학습, 결정·평가, 멀티미디어, 자기표현·관계.

## 뒤집으면 사람은 어떤 도구인가

LLM이 사람에게 주는 것은 지식과 텍스트다. 반대로 사람이 에이전트에게 줄 수 있는 것은 LLM에게 없는 것들이다.

- **감각:** 지금 밖의 날씨, 가게 진열대, 음식 맛
- **행동:** 몸을 움직이는 일, 현실 세계의 심부름
- **경험:** 오늘 한 일, 기억
- **취향과 판단:** 둘 중 무엇이 나은지

따라서 역전된 관계에서 사람은 에이전트의 **눈과 손, 그리고 평가자**다. 기존 코칭 용도("물 마셔")는 이 중 "손"을 쓰는 경우다.

## 범주별 대입

| 범주 | 사람 → LLM | 에이전트 → 사람 | 모델 표현 | 판정 |
|---|---|---|---|---|
| 정보 찾기 | "X가 뭐야?" | "편의점 가서 신상 뭐 나왔는지 보고 와", "지금 밖에 비 와?" | 목표 "알아낸다". 완료 조건 = 답을 받음 | 맞음 |
| 실용 안내 | "어떻게 해?" | 에이전트가 사용자에게 조언을 구함("나 이 상황이면 어떻게 해야 해?") | 목표 "조언 얻기" | 맞음. 다만 에이전트에게 실제 고민이 없으면 RP 연출이다(K4) |
| 글쓰기·편집 | "이 글 다듬어 줘" | "오늘 하루 세 줄로 써 와", "이 문장 더 자연스럽게 고쳐 봐" | 목표 + 결과물 확인 + 고쳐 오라는 이어가기 | 맞음. 결과물을 둘 곳이 없다(K1) |
| 학습 | "가르쳐 줘" | 에이전트가 퀴즈를 내거나, 사용자에게 무언가를 가르쳐 달라고 함 | 목표 "단어 20개", 진행 메모에 현황 | 맞음(조급한 Agent 시나리오의 `study`) |
| 결정·평가 | "A랑 B 중 뭐가 나아?" | "제목 후보 둘 중 골라 줘", "내가 쓴 시 몇 점이야?" | 목표 "사용자 평가 받기" | 맞음. 고르기 버튼이 있으면 응답률이 오른다(K2) |
| 멀티미디어 | 이미지 생성·해석 | "점심 사진 찍어 보내", "창밖 찍어 봐" | 목표 + 증거 | **안 맞음.** 1차 범위가 텍스트만이다(K3) |
| 자기표현·관계 | 잡담, 고민 상담, 롤플레이 | "심심해, 얘기하자", 에이전트가 자기 이야기를 함 | 목표 없는 흐름 | 맞음. 흐름은 목표 없이도 열린다 |

## 상호작용 성질 비교

| 성질 | 사람 → LLM | 에이전트 → 사람 | v4 장치 |
|---|---|---|---|
| 누가 여나 | 항상 사람 | 에이전트가 정한 시점 | 개시 예약 |
| 응답 지연 | 몇 초 | 몇 분에서 며칠 | 이어가기, 비동기 목표(`due_at`), 늦은 답 인식 |
| 거절·무응답 | 거의 없음 | 흔함 | 재촉 0회 이상 → 포기(`goal_close failed/dropped`) |
| 결과물 다듬기 | "다시", "더 짧게" | "다시 써 와" | 진행 메모 + 이어가기 |
| 병렬 | 채팅 여러 개를 동시에 | 흐름 1개, 목표는 여러 개 | 한 흐름에서 여러 목표를 다룸, 밀린 개입 정보 |
| 맥락 유지 | LLM이 잊어서 사람이 다시 설명 | 사람은 기억함. 에이전트가 잊음 | 활성 목표, 오늘 종료된 목표, memory(미정) |
| 비용 | 토큰 | 사람의 주의력 | 프롬프트가 빈도를 정함(D1) |
| 결과 검증 | 출력이 눈앞에 있음 | 현실 행동은 보고만 받음 | 완료 판정은 LLM, 증거 수신은 범위 밖 |

거의 모든 성질에 대응하는 장치가 이미 있다. 원래 설계가 "느리고 거절하는 도구"(사람)를 전제로 했기 때문이다.

## 발견한 것

| # | 내용 | 처리 |
|---|---|---|
| K1 | 사람이 만든 결과물(글, 답, 평가)을 에이전트가 나중에 다시 쓸 자리가 없다. 목표 사유는 한 줄이고, 원문은 지난 흐름의 메시지에 묻힌다 | memory 설계 범위. J2(무시한 메시지 기록)와 같은 축이다. "에이전트가 모은 것"을 memory에 어떻게 둘지 함께 정한다 |
| K2 | 평가·선택형 요청은 고르기 버튼이 있으면 응답 비용이 준다(LLM의 구조화 출력을 뒤집은 것) | 확장 지점. 텔레그램 인라인 키보드. 1차 범위 밖 |
| K3 | 감각을 빌리는 요청의 상당수가 사진을 필요로 한다 | §7 "증거 첨부" 항목에 근거를 하나 더함. 1차 범위 밖 유지 |
| K4 | 에이전트에게 "사용처"가 없으면 정보 찾기와 조언 구하기는 연출일 뿐이다. 사람은 LLM 출력을 자기 삶에 쓰지만, 에이전트의 삶은 대화와 기억뿐이다 | 하네스 변경 없음. 가치는 (a) 사용자에게 돌아가는 것(코칭, 하루 기록), (b) 에이전트 기억에 쌓여 다음 행동을 바꾸는 것에서 나온다. 방침 프롬프트가 둘 중 하나와 이어지게 쓴다 |

## 결론

뒤집힌 관계는 v4 모델에 구조적으로 들어맞는다. 일곱 범주 중 여섯이 목표(또는 목표 없는 흐름)로 그대로 표현된다. 사람이라는 도구의 성질(느림, 거절, 비동기)은 원래 설계의 전제여서, 새로 만들 하네스 장치는 없다. 걸리는 것은 결과물 보관(K1, memory)과 미디어 입력(K3, 범위 밖) 두 가지다.
