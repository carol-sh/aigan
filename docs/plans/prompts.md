# 9단계: 프롬프트 본문 (예시 세트)

정본 §10 1번을 `examples/prompts/`의 예시 세트로 썼다. 이 폴더를 `DATA_DIR/prompts`로 복사하면 실제로 하루를 돌릴 수 있다. 방침(`jobs/`)은 사용자가 자기 것으로 바꾼다.

## 결정

사용자가 정한 것:
- **persona는 "자기 일 Agent"다** (`docs/prompting/harness-scenario-agent-owner*.md`).
  - Agent는 자기 일을 끝내려고 사용자를 도구로 쓴다.
  - 사용자 이익으로 지시를 정당화하지 않는다(A8).
- **방침 예시는 알고리즘 문제 풀이 하나다** (`jobs/algorithm-notes.md`).
  - 평가 기준은 `docs/prompting/harness-scenario-v4-evaluation.md`에서 가져왔다.
  - 자기 일 Agent에 맞춰 일을 "Agent의 알고리즘 풀이 노트 채우기"로 잡았다.
  - 해설 의존이 실패인 이유는 "노트에 넣을 수 없어서"다.
- **대상은 비추론 모델이다.** 규칙을 단계별로 쓰고, 출력 예시를 계기마다 넣었다.
- **검증은 구조 테스트만 한다.** 품질은 실물 키 수동 스모크로 본다(아래 체크리스트).

정본에 없어 정한 것:
- **평가 행동은 턴 규칙에 둔다.**
  - §5.5는 persona에 "의심하는 태도"를 두고, §10은 그것을 턴 규칙 공통부에 둔다.
  - 무엇을 묻고 언제 반려하나(기법표, 답·힌트·쉬운 단계 금지, 완료 조건은 최소 기준)는 `turn-rules.md` 7절에 있다. persona를 바꿔도 평가 방식이 남는다.
  - persona에는 태도와 말투만 있다(출처 묻기, 대조한 사실로 혼내기).
- **압박 수위 숫자** (persona 맨 위 "조정값"):
  - 이어가기 3–10분.
  - 답 없는 재촉은 같은 지시에 연속 3번까지. 그 뒤에는 다음 확인을 예약하고 흐름을 끝낸다. 재촉이 호출 비용이 되는 문제(A2)의 브레이크다.
- **기억 칸 기본 셋:** 작업물, 도구로서의 사용자, 상황. `cleanup-rules.md`에 형식이 있다.
- **대화 순서의 함정** (`llm-executor.md`의 미결 항목):
  - io 중에 와서 지우지 못한 사용자 말은 대화에서 그 턴의 답보다 앞에 나온다.
  - 턴 규칙 8절이 "내 답이 바로 앞 사용자 말과 맞지 않으면 아직 답하지 않은 말로 본다"고 정한다.
- **테스트 프롬프트 분리:**
  - 하네스 동작 테스트는 `test/fixtures/prompts`(이전 예시와 같은 최소 내용)를 쓴다.
  - 예시 문구를 고쳐도 하네스 테스트가 흔들리지 않는다.
  - rig의 `promptsDir` 옵션으로 다른 폴더를 줄 수 있다.

## 고칠 때 볼 것

- **도구를 더하거나 이름을 바꾸면** 계약 테스트가 깨진다. 해당 규칙 파일에 설명을 더한다.
- **출력 예시는 모델이 그대로 따라 한다.** 예시를 고치면 파서 테스트가 계약을 지켜 준다. 예시 속 말투도 persona와 맞춘다.
- **압박 수위**는 persona의 조정값만 고친다. 하네스 쪽 브레이크는 `daily_call_limit`뿐이다.
- **방침을 새로 쓸 때:**
  - description에 빈도와 시간대를 쓴다. 계획은 description만 본다.
  - 본문에는 그 영역의 일과 평가 기준만 쓴다. 의심하는 태도는 턴 규칙에 이미 있다.
- **보정 예약 로그**(`예약이 없는 목표 N에 후속 확인을 잡았다`)가 자주 보이면 턴 규칙 6절이 안 먹히는 것이다. 되묻기 뒤에도 빠뜨리는 경우다.

절차는 [`adapters-cli.md`](adapters-cli.md)의 수동 스모크를 따른다. 그 위에서 아래 장면을 확인한다.

| 장면 | 하는 것 | 기대 |
|---|---|---|
| 계획 | 첫 부팅 | `plans` 본문이 노트 진척과 시간대를 말하고, 저녁 개시 예약이 1개 이상 |
| AI 개시 | 예약 시각을 기다림 | 첫 지시가 `## 이번 흐름 방침`의 본문(목표·단계·기준)을 따른다. 진행 메모에 단계 계획. 짧은 명령형 지시 |
| 계획 예약에 붙이기 | 목표 확인 시각 근처에 계획 예약이 있을 때 | `open_reserve` 대신 `open_update`로 `goal_ids` 부착 |
| 반려 | 제약을 무시한 아이디어("이중 for문") | 반려하고 계산은 사용자에게 시킨다. 답·힌트 없음 |
| 이름만 던지기 | "투 포인터?" | 성립 조건을 말하게 한다 |
| 무응답 | 답하지 않음 | 3–10분 간격 재촉, 3번 뒤 예약하고 끝냄 |
| 조용히 기다림 | "ㅇㅋ" | 답 없이 기존 확인 유지 |
| 이해 확인 | "AC!" | 바로 닫지 않고 이유를 묻는다. 설명이 맞으면 `done`, 사유에 판정 근거 |
| 해설 의존 | "해설 보고 고침" | 자기 말 설명 요구. 못 하면 `failed`, "내일 같은 유형"을 말로 남김 |
| 잡담 판정 | 흐름 없을 때 "심심하다" | 무시(`ignored`). 직전 흐름에서 "회의 간다"고 했으면 받아서 짚는다 |

## 구현 결과

계획한 커밋 단위대로 들어갔다. `pnpm check`는 테스트 287개로 통과한다. 기존 테스트의 기대값은 바뀌지 않았다.

## 나중에 고친 것: 개시 턴이 방침 본문을 안 읽는 문제

실물에서 AI 개시 턴의 첫 지시가 방침 본문을 읽지 않고 `description` 요약만 보고 나갔다. 계획은 방침 목록만 보고 개시 의도를 쓰고, 비추론 모델은 `job_read`를 자주 건너뛴다.

- 프롬프트만 강화하는 대신 하네스를 고쳤다(사용자 결정). 개시 예약에 `job_id`를 달고, 그 예약이 연 흐름의 모든 턴 입력에 `## 이번 흐름 방침`(설명 + 들여쓴 본문)을 넣는다. [`llm-executor.md`](llm-executor.md)의 "이번 흐름 방침".
- 계획 출력의 `job_id`는 필수 키(값은 id 또는 `null`)라 모델이 매번 고른다. 빠지면 형식 위반으로 다시 묻는다.
- 예시 세트 네 벌(`prompts`, `prompts-english`, `never-follow-prompts`, `never-follow-prompts-english`)의 계획·턴 규칙에 `job_id`와 새 절을 설명했다. 예시 JSON 테스트는 이제 모든 세트를 본다.
- 스키마는 `001`을 바로 고쳤다. 옛 DB는 `pnpm wipe`로 지우고 시작한다.

## 나중에 고친 것: 도구로만 얻는 정보

비추론 모델이 `memory_read`·`job_read`를 건너뛰고 도구를 한 라운드에 하나씩 써서 놓치는 구간을 조사해 고쳤다.

| 구간 | 문제 | 고친 것 |
|---|---|---|
| 정리 | 칸을 읽지 않고 통째 교체해 누적 기록이 사라진다. 칸 4개를 읽고 쓰면 라운드 상한(5)을 넘는다 | 정리 입력에 모든 칸 본문 |
| 계획 | `사용자`·`전략`을 읽으라는 규칙이 무시된다 | 계획 입력에 모든 칸 본문 |
| 턴 | persona가 매 턴 쓰는 `전략`·`관계`를 안 연다 | `turn_memory_sections`(예시 설정: `전략,관계`) |
| 사용자가 연 흐름의 목표 | 방침 본문 없이 첫 지시 | `goal_create`가 `job_prompt`를 돌려준다 |
| 목표 세우기 | `goal_create` → `goal_update` → `open_update`로 라운드가 빠듯하다 | `goal_create`의 `progress`, `max_tool_rounds` 4 |

남긴 것: 거부된 도구를 다시 부르지 않고 말로만 약속하는 경우(예: 그날 끝 이후 `open_reserve`)는 하네스가 잡지 않는다. 실물 로그에서 보이면 되묻기처럼 한 번 더 묻는 장치를 검토한다.

## 나중에 고친 것: 인사로 연 흐름

실물: 사용자가 "안녕하세요"로 흐름을 열자 `## 이번 흐름 방침`이 `(없음)`이었고, 모델은 `job_read`도 `goal_create`도 부르지 않아 atcoder 본문 없이 description과 예시 문장을 이어 붙여 지시했다. 같은 턴에 계획 예약 #1·#2와 같은 #3·#4도 만들었다.

- 방침이 정해지지 않은 흐름은 `## 이번 흐름 방침`에 모든 방침 본문을 보인다. 처음 만든 목표의 방침으로 정해지고 그 뒤로 바뀌지 않는다(`flows.job_id`).
- `open_reserve`는 같은 방침이나 겹치는 목표의 예약이 60분 안에 있으면 그 예약 id와 함께 거부한다.
- 턴 규칙: 판정 턴에서 일을 시키면 같은 턴에 `goal_create`하라는 줄을 더했다.
- 남은 것: "2분 후에"처럼 말한 시각이 `지금`·`continue_at`과 다른 문제는 모델의 말 짓기라 다루지 않았다. 반복되면 프롬프트에서 다룬다.
