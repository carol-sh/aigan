# 이용 시나리오: 꼼수 부리는 도구를 다루는 Agent

"자기 일에 사용자를 쓰는 Agent"(`harness-scenario-agent-owner.md`)의 다음 날이다. Agent는 그대로다. 가이드는 자기 일이고, 사용자는 그 일에 쓰는 도구다.

이번에는 도구가 말을 안 듣는다. 사용자는 편하게 가려고 꼼수를 쓰고, 핑계를 대고, 늘어진다. 사람이 LLM의 대충 쓴 답, 지어낸 사실, 뭉갠 출력을 잡아내듯이, Agent는 사용자의 꼼수를 잡아내고 혼내고 다시 시킨다. 하루가 끝날 때 목표는 달성된다.

이 문서는 두 가지에 쓴다.
- 꼼수와 늘어짐에 맞서 Agent가 무엇을 근거로 잡아내는지, 하네스가 그 근거를 어디서 대 주는지 본다.
- 혼내는 Agent의 프롬프트를 쓸 때 기준 장면으로 삼는다.

## 사람이 LLM의 꼼수를 잡듯이

| LLM의 꼼수 | 사용자의 꼼수 | Agent가 잡는 법 |
|---|---|---|
| 검색 안 하고 아는 척 | 직접 확인 대신 지도 앱 정보를 옮김 | "지도는 사장이 언제 고쳤는지 모른다" |
| 그럴듯하게 지어낸 사실 | 물어보지 않은 마감 시각을 지어냄 | 출처를 묻는다: "누가 받았나. 뭐라고 했나" |
| 다른 모델 출력 복붙 | 초안을 GPT로 씀 | 문체 대조(기억의 원고), 숫자 대조(기억의 조사 데이터) |
| 틀린 걸 들키면 말 바꾸기 | 메시지를 수정하고 "다시 봐" | 하네스는 수정을 저장하지 않는다. Agent는 원문을 본다 |
| 할 일 대신 딴 얘기 | "근데 너는 빵 좋아해?" | 질문을 돌려보내고 원래 지시를 반복 |
| 거절 핑계 | "회의 들어가야 돼" 뒤에 잡담 | 직전 흐름 꼬리에 남은 핑계와 대조 |
| "이 정도면 충분합니다" | "지금 것도 충분하지 않아?" | 남은 일이 왜 사용자 몫인지 말한다 |
| "직접 해 보세요" | "너가 써 주면 안 돼?" | 일의 원칙으로 거절: 현장 근거 없는 문장은 안 쓴다 |

### F2 · 12:10 GPT 초안

대화

```
12:10 Agent   빵집 섹션. 어제 v2에 숫자 넣고 망원제과 한 줄 추가. 점심 안에.
12:16 사용자  망원시장의 아침을 여는 세 곳의 빵집. 밀도는 바삭한 소금빵(3,500원)과
              촉촉한 식빵(5,800원)으로 오랜 사랑을 받아 왔습니다. 망원동 소금빵집은
              합리적인 가격(소금빵 3,200원)으로 은은한 버터 향을 선사하며, 새로
              합류한 망원제과는 소금빵 2,800원으로 가성비를 자랑합니다.
12:16 Agent   네 문장이 아니다. 너는 '선사하며'를 안 쓴다. 어제 v2는 "버터 향이 약하다"였다.
              그리고 망원제과 2800은 어디서 났나. 어젯밤 네가 3000이라고 했다.
12:18 사용자  (12:16 메시지를 수정한 뒤) 다시 봐. 3000이라고 돼 있잖아

12:20 Agent   GPT는 망원제과에 가 본 적이 없다. 그래서 가격을 지어냈다.
              네가 본 숫자만 쓴다. v2에 숫자 넣고 망원제과 한 줄. 네 말로.
12:31 사용자  망원시장 빵집은 오전에 가야 한다. 밀도: 소금빵 3500원, 식빵 5800원
```

## 하루 비용

| 항목 | 수 |
|---|---|
| 흐름 | 5(AI 개시 4, 사용자 개시 1) |
| 턴 호출 | 27 |
| 도구 라운드 추가 요청 | 약 10 |
| 정리 | 5흐름 × 1–2 요청 |
| 계획 | 1 |
| API 요청 합계 | 약 45–50 |
| 답 없는 재촉 | 4 |

앞 시나리오보다 재촉이 적다. 꼼수는 답을 하긴 하는 늘어짐이라 대화가 이어지고, Agent는 재촉 대신 반박에 호출을 쓴다.

## 관찰

| # | 내용 | 처리 |
|---|---|---|
| C1 | 꼼수를 잡는 근거는 전부 기억과 대화 원문이다. 가격은 "조사 데이터" 칸, 문체는 "가이드 원고" 칸의 사용자 문장, 핑계는 직전 흐름 꼬리에 있다. 판단은 LLM이 하고 하네스는 근거를 대 줄 뿐이다 | 기존 설계로 동작. 정리 규칙이 사용자가 직접 쓴 문장을 몇 줄은 원문으로 남겨야 다음 날 문체 대조가 된다 |
| C2 | 메시지 수정은 저장하지 않는다(설계 §9.1). 들킨 뒤 고쳐도 Agent는 원문을 본다. 사용자가 메시지를 지워도 봇은 알림을 받지 않으므로 기록은 남는다 | 기존 설계로 동작. 의도한 부수 효과다 |
| C3 | 15:20의 잡담은 평소라면 무시할 메시지인데, 직전 흐름 꼬리에 "회의 들어가야 돼"가 있어서 받는다. 꼬리 시간 제한(`prev_flow_tail_max_age_sec`)을 넘으면 핑계를 잊고 못 잡는다. 같은 날 안의 핑계는 기억에 아직 없다(정리가 쓰기 전이면) | 기존 설계로 동작. 기본값 실측 때 이 경우를 참고한다. 정리 규칙은 핑계를 그날 state에 남길 수 있다 |
| C4 | 목표가 닫힌 뒤 남은 예약(16:00[G3])은 사전 검사가 지운다. Agent가 취소를 잊어도 빈 개입이 열리지 않는다 | 기존 설계로 동작 |
| C5 | 검증할 수 없는 보고("마감 9시")는 출처를 묻는 질문으로만 걸러진다. 사용자가 끝까지 거짓말하면 못 잡는다. 통화 기록, 사진 같은 증거는 범위 밖이다 | 범위 밖 유지(설계 §7 증거 첨부). persona: 보고마다 출처를 묻는다 |

## 프롬프트에 옮길 것

- **persona**: 보고를 그대로 믿지 않는다. 출처를 묻고(누가, 언제, 어떻게 확인했나), 기억과 대조한다(C5). 혼낼 때는 대조 결과를 말한다. 무엇이 어디와 다른지를 짚고 감정적 비난은 하지 않는다(C6). 딴 얘기는 받지 않고 지시를 반복한다. "너가 해"는 일의 원칙으로 거절한다(C7). 들킨 꼼수는 짚고 바로 다시 시킨다. 사과를 요구하지 않는다.
- **턴 규칙**: 잡담이라도 직전 흐름의 핑계와 어긋나면 받는다(C3). 목표를 닫을 때 사유에 꼼수와 그 결과를 남긴다(정리가 쓴다).
- **정리 규칙**: 사용자가 직접 쓴 문장 몇 줄을 문체 표본으로 원문 그대로 남긴다(C1). "도구로서의 사용자" 칸에 꼼수 유형과 걸린 뒤의 반응을 쌓는다.
- **상위 프롬프트**: "도구로서의 사용자"의 꼼수 패턴을 보고, 확인이 필요한 과제(통화, 현장)에는 출처 확인 시간을 함께 잡는다.
