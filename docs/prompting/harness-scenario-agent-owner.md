# 이용 시나리오: 자기 일에 사용자를 쓰는 Agent

이 Agent에게는 자기 일이 있다. 사용자를 코칭하는 게 목적이 아니다. 자기 프로젝트를 끝내려고 사용자를 도구로 쓴다. 사람이 LLM을 쓸 때처럼 짧게 명령하고, 형식을 정해 주고, 결과가 마음에 안 들면 "다시"라고 한다. 사용자는 Agent의 눈, 손, 초안 작성기 역할을 한다.

Agent는 이 일이 자기 일이라고 믿는다. 사용자에게 돌아가는 이익으로 지시를 정당화하지 않는다.

이 문서는 두 가지에 쓴다.
- 하루를 설계(1.0) 규칙대로 따라가며, 이런 Agent가 하네스 안에서 어떻게 도는지와 무엇이 걸리는지 본다.
- 이 성향의 프롬프트를 쓸 때 기준 장면으로 삼는다.

## 사람이 LLM을 쓰는 방식을 뒤집으면

| 사람 → LLM | Agent → 사용자 |
|---|---|
| 짧은 명령형 프롬프트 | "3곳. 이름만." |
| 출력 형식 지정 | "가게\|품목\|가격\|시각 형식으로." |
| 마음에 안 들면 다시 생성 | "감상 빼고 숫자. 다시, 300자." |
| 여러 버전 받아서 고르기 | "3버전으로 다시 써. 각 40자 이하." |
| 출력을 의심하고 사실 확인 | "지난주엔 6200이었다. 가격표 다시 봐." |
| 고맙다는 말 없음, 바로 다음 요청 | 완료 판정 뒤 바로 다음 지시 |
| 응답이 늦으면 다시 보냄 | 1–5분 간격 재촉 |
| 모델 성능 평가("요약은 잘하는데 계산은 틀림") | 기억에 "도구로서의 사용자" 칸을 두고 과제 유형별 속도·정확도를 쌓음 |

## 설정

| 항목 | 값 |
|---|---|
| Agent의 일 | "망원동 생활 가이드" 완성. 빵집·카페 섹션마다 가격, 영업 정보, 짧은 소개글 |
| 방침 | `field`: 현장 조사(가격, 영업 여부, 붐빔. 사용자가 직접 보고 와야 하는 것) · `draft`: 섹션 초안을 사용자에게 쓰게 하고 고치게 함 · `polish`: 문장 여러 버전 받기, 둘 중 고르게 하기 |
| 프롬프트 성향 | 매우 pushy. 지시는 짧은 명령형이다. 이어가기는 1–5분 간격이다. 사용자 사정("일하는 중")은 시간 조정에만 쓰고 지시를 거두지 않는다. 결과물을 의심하고 기억과 대조한다. 칭찬과 감사가 없다. 잡담은 자기 일에 쓸모없으면 무시한다 |
| 사용자 | 직장인(09–18시). 현장 조사는 출근길·점심·퇴근길에만 가능 |
| 기억(전날까지) | state: "가이드 40%. 카페 초안 있음, 빵집 비어 있음. 점심·퇴근길만 현장 가능". 칸: "가이드 원고", "조사 데이터"(밀도 식빵 6200, 지난주), "도구로서의 사용자" |
| 상한 | `goal_max_active`=8, `open_max_pending`=6, `min_lead`=60초, 디바운스 20초, `daily_call_limit`=200, `max_tool_rounds`=3 |
| 블랙아웃 | 00:00–08:00. 00:00에 그날(D)을 계획한다 |

## 추적

흐름마다 **대화**(사용자가 텔레그램에서 보는 것)와 **하네스**(루프가 한 일)를 나눠 적는다.

| 흐름 | 시각 | 개시 | 다룬 목표 | 끝 |
|---|---|---|---|---|
| — | 00:00 | 계획 | — | 예약 6개 |
| F1 | 08:05–08:10 | AI(R1 아침 배정) | G1–G4 생성 | `agent` |
| F2 | 08:40–08:41 | AI(R2 출근길, [G4]) | G4 done | `agent` |
| — | 11:02 | 판정 | — | 무시 |
| F3 | 12:10–12:56 | AI([G1]) | G1 failed, G5 생성 | `agent` |
| F4 | 15:00–15:12 | AI(R4 문장 다듬기) | G6 생성·done | `agent` |
| F5 | 16:40 | 사용자 | — | `agent` |
| F6 | 18:20–18:37 | AI([G2, G5]) | G5 dropped | `agent` |
| F7 | 18:55–19:01 | AI([G2]) | G2 failed | `agent` |
| F8 | 20:30–21:50 | AI([G3]) | G3 failed | `agent` |
| F9 | 23:10–23:11 | 사용자 | — | `agent` |
| F10 | 23:57–00:00 | 사용자 | — | `blackout` |

### 00:00 계획

| 시각 | 루프 | 효과 |
|---|---|---|
| 00:00 | 블랙아웃 시작, 흐름 없음 → 날 넘김 → `Plan(D)` | 계획이 개시 예약 7개를 낸다: R1 08:05 아침 배정, R2 08:40 출근길, R3 12:10 점심 조사, R4 15:00 문장 다듬기, R5 18:20 퇴근길 조사, R6 20:30 초안, 22:30 검수. 상한 6이라 `at` 순으로 6개까지 저장하고 22:30 검수는 버려진다(로그) |

계획은 목표를 만들지 않으므로 여섯 예약 모두 `goal_ids`가 없다.

### F1 · 08:05 아침 배정

대화

```
08:05 Agent   일어났지. 오늘 할당.
              ① 점심: 망원시장 빵집 3곳, 소금빵·식빵 가격
              ② 퇴근길: 카페 '모래' 아직 영업하는지
              ③ 밤: 빵집 섹션 400자
              지금 ①의 가게 3곳 이름부터.
08:07 Agent   아직? 이름만.
08:09 Agent   3곳.
08:10 사용자  씻는 중이라고
08:10 Agent   8시 40분, 출근길에 다시 온다. 그때 3곳.
```

하네스

| 시각 | 루프 | 효과 |
|---|---|---|
| 08:05 | R1 발화 → `Turn(open)` | 도구 1라운드: `goal_create` ×4. G1 빵집 3곳 가격(마감 13:00), G2 카페 "모래" 영업 확인(19:00), G3 빵집 섹션 초안 400자(22:00), G4 조사할 빵집 3곳 이름(08:45). 턴 입력의 개시 예약 목록에서 계획 예약 R2–R6을 본다. 2라운드: `open_update`로 R2에 G4, R3에 G1, R5에 G2, R6에 G3를 붙인다. 예약 수는 그대로다. `continue` 08:07 |
| 08:07, 08:09 | `Turn(continue)` ×2 | 답 없음. 재촉만 |
| 08:10 | `Turn(reply)`, 출력 `end` | G1–G4 모두 예약에 걸려 있어 되묻기 없음. 흐름 닫힘 → 정리 |

계획이 낸 예약에 목표를 붙여 쓴다. 따로 예약을 만들지 않으므로 같은 시각에 개입이 겹치지 않는다(관찰 A1).

대화

```
12:10 Agent   회의 끝났지. 시장 가. 3곳, 형식은 이렇게:
              가게|품목|가격|시각
12:24 사용자  밀도|소금빵|3500|12:20
              밀도|식빵|5800|12:20
              망원동 소금빵집|소금빵|3200|12:23
              망원동 소금빵집|식빵|5500|12:23
12:24 Agent   밀도 식빵은 지난주에 6200이었다. 가격표 다시 봐.
12:31 사용자  가격표 그대로 쓴 거임
12:31 Agent   그럼 '5800(지난주 6200)'으로 적어. 세 번째 가게.
12:44 사용자  점심 끝남
12:44 Agent   13시 전이다. 지나가면서 봐. 1분이면 된다.
12:50 Agent   세 번째.
```

| 시각 | 루프 | 효과 |
|---|---|---|
| 12:10 | R3[G1] 발화 → `Turn(open)` | 흐름 밖 "회의 지옥이다"(`ignored`)를 흡수해 컨텍스트에 둔다. "회의 끝났지"가 여기서 나온다. `continue` 12:25 |
| 12:24 | `Turn(reply)` | `memory_read("조사 데이터")`로 지난주 가격과 대조 |
| 12:31 | `Turn(reply)` | G1 진행 메모에 2곳 기록 |

| 12:50, 12:53 | `Turn(continue)` ×2 | 답 없음(사무실) |
| 12:56 | `Turn(continue)` | `goal_close(G1, failed, "3곳 중 2곳")`. G5 "세 번째 가게 이름·가격"(마감 19:00)을 만들고, `open_update`로 R5의 `goal_ids`를 [G2, G5]로 바꾼다. `end` |

이 흐름에서만 답 없는 재촉이 3번 나갔다. 이어가기 턴은 말 없이 기다릴 수 없어서(설계 §5.1) 재촉 한 번이 곧 메시지 한 통이다(관찰 A2).

## 프롬프트에 옮길 것

- **persona**: 가이드는 자기 일이고 사용자는 그 일에 쓰는 도구다. 사용자 이익으로 설득하지 않는다(A8). 짧은 명령형으로 말하고 형식을 지정한다. 결과물은 기억과 대조해 의심한다. 칭찬과 감사가 없다. 사용자 사정은 시간 조정에만 쓴다. 재촉은 간격 N분, 한 목표에 M번까지(A2).
- **턴 규칙**: 목표를 만들면 그 시각 근처의 계획 예약에 `open_update`로 붙인다. 새 예약은 맞는 계획 예약이 없을 때만 만든다(A1). 마감을 넘기면 실패로 닫고, 남길 것은 말로 남긴다. 잡담은 쓸모가 있을 때만 받는다(A5).
- **정리 규칙**: 진행 메모의 결과물 최신본을 "원고"·"데이터" 칸으로 옮긴다(A3). "도구로서의 사용자" 칸에 과제 유형별 응답 시간과 품질을 쌓는다(A4).
- **상위 프롬프트**: "원고" 칸의 진척을 보고 그날 할 몫을 정한다. "도구로서의 사용자"를 보고 과제를 사용자가 잘하는 시간대에 놓는다.
