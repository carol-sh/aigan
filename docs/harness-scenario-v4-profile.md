# v4 이용 시나리오 3: 사용자 프로파일링(일기 대신 묻기)

일을 시키는 대신 사용자에 대해 자유롭게 묻는다. "지금 뭐 해?", "오늘 어디 다녀왔어?" 같은 질문으로, 사용자가 직접 쓰지 않아도 하루가 기록되게 하는 것이 가치다.

## 설정

| 항목 | 값 |
|---|---|
| 방침 | `profile`: 사용자를 알아가고 하루를 기록하기. 하루 3–5회, 상황에 맞는 열린 질문. 답이 없으면 1회까지만 다시 묻고 접는다 |
| 함께 도는 방침 | `health`(물) |
| 블랙아웃 | 01:00–08:00 |

목표 사용: 질문은 완료 조건이 있는 일이 아니므로 목표를 만들지 않는다. 계획이 낸 개시 예약의 `intent`만으로 흐름이 열린다(`goal_ids` 없음, I3 대상 아님). 꼭 확인해야 하는 후속(예: "병원 결과 나오면 알려줘")만 목표로 만든다.

## 추적

### 08:00 계획

| 시각 | 사건 | 결과 |
|---|---|---|
| 08:00 | 계획 | 개시 예약: 10:30 "지금 뭐 하는지", 13:00 "점심", 19:30 "오늘 어디 다녀왔는지", 22:30 "하루 어땠는지" |

### 10:30 지금 뭐 해?

```
[10:30] 봇   지금 뭐 하고 있어?
[10:34] 나   회의 들어가기 전에 자료 보는 중
[10:34] 봇   무슨 회의야?
[10:35] 나   분기 계획. 좀 길어질 듯
[10:35] 봇   알겠어. 끝나고 어땠는지 나중에 물어볼게
```

흐름 `F1` 종료. 턴이 `open_reserve`(12:30, "분기 계획 회의 어땠는지")를 추가. 정리가 memory에 "오늘 분기 계획 회의"를 남긴다(memory 설계 미정).

### 12:30–13:00 이전 대화를 이어받아야 하는 질문

| 시각 | 사건 | 루프 | 결과 |
|---|---|---|---|
| 12:30 | "회의 어땠는지" 개시 | 턴 입력: 방침, 활성 목표, 계획, 이 흐름 대화, 직전 흐름 이후 흐름 밖 메시지, memory 슬롯 | **허점 J1**: 10:30 흐름의 대화는 턴 입력에 없다. `intent` 문장과 memory(미정)만 의지한다. memory가 요약을 놓치면 "무슨 회의?"를 다시 묻는다 |
| 13:00 | "점심" 개시 | 같은 구조 | AI가 회의 흐름이 방금 끝난 걸 모르고 점심 질문을 따로 연다(합쳐도 될 개입). 오늘 이미 나눈 대화를 볼 수 없으니 판단 재료가 없다 |

### 15:20 사용자가 먼저 공유

```
[15:20] 나   카페 왔어. 일 좀 하려고
```

| 시각 | 사건 | 루프 | 결과 |
|---|---|---|---|
| 15:20 | 흐름 없음 → 판정 | AI가 답할 필요 없다고 보고 `respond=false` | `ignored`. 사용자에게는 침묵 |
| | | **허점 J2**: 무시한 메시지는 흐름에 들어가지 않으므로 정리(memory)에 올라가지 않는다. 다음 흐름의 컨텍스트에는 들어가지만, 그 흐름의 정리 입력은 흐름 메시지뿐이라 결국 기억되지 않을 수 있다 | 일기 관점에서 "카페에서 일함"이 사라진다 |

### 19:30 답 없는 질문, 늦은 답

| 시각 | 사건 | 결과 |
|---|---|---|
| 19:30 | "오늘 어디 다녀왔어?" 개시, 무응답 | 19:45 한 번 더 묻고 무응답 → AI `end` |
| 21:10 | 사용자 "성수동 갔다 왔어. 전시 봤어" | 흐름 없음 → 판정 → 받음. 질문했던 흐름은 닫혔지만, J1 때문에 AI는 이 말이 19:30 질문의 답인 줄 모른다. 내용으로 추측만 한다 |

### 22:30 하루 어땠어

```
[22:30] 봇   오늘 하루 어땠어?
[22:41] 나   피곤했는데 전시는 좋았어
[22:41] 봇   다행이다. 푹 쉬어
```

하루가 끝났다. 사용자가 쓴 건 없지만 대화는 여러 흐름에 흩어져 있다.

| 시점 | 질문 | 현재 설계 |
|---|---|---|
| 다음 날 | "어제 뭐 했더라?" 사용자가 볼 기록이 있나 | **허점 J3**: 없다. memory는 AI가 쓰는 내부 기억이고, 사용자가 읽는 일기 형태의 산출물을 만드는 접점이 없다. 일기 대신이라는 가치가 실현되지 않는다 |

## 발견한 허점

| # | 허점 | 제안 |
|---|---|---|
| J1 | 턴이 오늘의 이전 흐름 대화를 보지 못함. memory가 미정이라 같은 날의 연속성이 전적으로 memory 품질에 달림 | 턴 입력에 "오늘(현재 계획일)의 이전 흐름 대화"를 넣는다. 길면 정리 요약으로 대체. memory 설계와 별개로 하루 단위 단기 기억을 하네스가 보장한다 |
| J2 | 무시한 흐름 밖 메시지가 기록·기억에 남지 않음 | 하루 마감 작업(J3)이 그날의 모든 메시지(무시 포함)를 입력으로 받으면 자연히 해결. 별도 장치 불필요 |
| J3 | 사용자가 읽는 기록(일기)을 만드는 접점이 없음 | 새 LLM 접점 **하루 마감**: 계획일이 끝날 때(블랙아웃 시작 시) 그날 모든 메시지를 보고 일기 1편을 만든다. memory 갱신도 겸할 수 있다 |

## 확인된 것

- 목표 없이 `intent`만 가진 개시 예약으로 질문 흐름이 잘 돈다. 질문을 목표로 만들지 않으면 I3 보정이 끈질긴 재질문을 만들지 않는다.
- 늦은 답은 수신 판정으로 받아진다. 흐름이 닫혔어도 대화가 끊기지 않는다(J1 해결 시 문맥까지 이어짐).
- 블랙아웃 직전(22:30) 질문 흐름도 무응답이면 블랙아웃 이어가기에서 닫힌다.

## 결정 필요

| # | 질문 | 선택지 |
|---|---|---|
| D3 | 하루 마감 작업을 둘까 | (가) 둔다: 블랙아웃 시작 시 일기 생성 (나) 두지 않고 memory 설계에서 다룬다 |
| D4 | 일기를 어디에 두고 어떻게 보여줄까 | (가) 파일만(`journal/YYYY-MM-DD.md`) (나) 파일 + 다음 날 아침 첫 흐름에서 전송 (다) 파일 + 사용자가 물으면 AI가 참조 |
| D5 | J1의 "오늘 이전 흐름" 범위 | (가) 원문 전부(길면 잘라냄) (나) 각 흐름의 정리 요약 (다) memory 설계에서 함께 정함 |
