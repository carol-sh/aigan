# v4 이용 시나리오 3: 사용자 프로파일링(일기 대신 묻기)

일을 시키는 대신 사용자에 대해 묻는다. "지금 뭐 해?", "오늘 어디 다녀왔어?" 같은 질문으로, 사용자가 직접 쓰지 않아도 하루가 기록되게 하는 것이 가치다.

프로파일링도 "일"로 추상화한다. 목표를 "사용자가 지금 무엇을 하는지 확실히 알아낸다"로 잡으면 완료 조건("사용자가 답함")이 생기고, 나머지는 시키는 일과 똑같이 돈다. 답이 없으면 재촉하고, 포기 시점은 프롬프트가 정한다.

## 설정

| 항목 | 값 |
|---|---|
| 방침 | `profile`: 사용자를 알아가고 하루를 기록하기. 하루 3–5회 |
| 함께 도는 방침 | `health`(물) |
| 블랙아웃 | 01:00–08:00 |

## 추적

### 01:00 계획

| 시각 | 사건 | 결과 |
|---|---|---|
| 01:00 | 계획(블랙아웃 진입) | 개시 예약: 10:30 "지금 하는 일 파악", 13:00 "점심", 19:30 "오늘 다녀온 곳", 22:30 "하루 소감" |

### 10:30 지금 뭐 해?

```
[10:30] 봇   지금 뭐 하고 있어?
[10:34] 나   회의 들어가기 전에 자료 보는 중
[10:34] 봇   무슨 회의야?
[10:35] 나   분기 계획. 좀 길어질 듯
[10:35] 봇   알겠어. 끝나고 어땠는지 물어볼게
```

| 턴 효과 | 내용 |
|---|---|
| `G1` "지금 하는 일 알아내기" | 생성 → `done`, 사유 "분기 계획 회의 준비 중" |
| `G2` "분기 계획 회의 결과 알아내기" | 생성, 진행 메모 "회의 길어질 듯", `open_reserve`(12:30, [G2]) |

### 12:30 이전 대화를 이어받기

| 시각 | 사건 | 결과 |
|---|---|---|
| 12:30 | `G2` 예약 개시 | 턴 입력의 활성 목표에 `G2`와 진행 메모가 있다. "분기 계획 회의 어땠어?"를 문맥대로 묻는다. **활성 목표의 진행 메모가 흐름 사이 단기 기억 역할을 한다** |
| 12:40 | 사용자 "결국 내 안이 통과됨" | `G2` done, 사유 "분기 계획에서 사용자 안 통과". 밀린 목록에 13:00 점심 예약이 없으므로(아직 scheduled) 흐름 종료 |
| 13:00 | "점심" 개시 | **허점 J1**: `G1`, `G2`는 이미 `done`이라 턴 입력에서 빠진다. AI는 30분 전 안이 통과된 걸 모른 채 점심만 묻는다. "축하 겸 맛있는 거 먹었어?" 같은 연결이 안 된다 |

### 15:20 사용자가 먼저 공유

```
[15:20] 나   카페 왔어. 일 좀 하려고
```

| 상황 | 결과 |
|---|---|
| 관련 활성 목표가 있음(예: "오후 일정 알아내기") | AI가 받아서 목표를 닫는다. 기록된다 |
| 관련 목표가 없음 | AI가 무시할 수 있다. **허점 J2**: 무시한 메시지는 어느 흐름에도 들어가지 않아 목표 사유로도, 정리(memory)로도 남지 않는다 |

### 19:30 답 없는 질문, 늦은 답

| 시각 | 사건 | 결과 |
|---|---|---|
| 19:30 | `G3` "오늘 다녀온 곳 알아내기" 개시, 무응답 | 19:45 재촉, 무응답 → AI가 흐름을 닫고 `open_reserve`(21:00, [G3]) |
| 21:00 | 재개시, 무응답 | 흐름 종료. G3는 활성으로 남고 I3 보정이 다음 확인을 잡는다 |
| 21:10 | 사용자 "성수동 갔다 왔어. 전시 봤어" | 판정. 활성 목표 `G3`가 입력에 있으므로 AI가 이것을 G3의 답으로 알아본다 → 받음, G3 done. 늦은 답 문제는 목표 모델이 해결한다 |

### 22:30 하루 소감, 그리고 다음 날

```
[22:30] 봇   오늘 하루 어땠어?
[22:41] 나   피곤했는데 전시는 좋았어
[22:41] 봇   안 통과에 전시까지, 꽤 괜찮은 하루였네. 푹 쉬어
```

마지막 줄은 J1이 해결됐을 때 가능한 답이다.

하루가 끝나면 그날 `done` 목표들의 사유가 그대로 하루 기록이 된다: "분기 계획 회의 준비", "사용자 안 통과", "카페에서 작업", "성수동 전시", "피곤했지만 전시 좋았음".

| 시점 | 질문 | 현재 설계 |
|---|---|---|
| 다음 날 | 사용자가 읽을 기록이 있나 | **허점 J3**: 없다. 재료(목표 사유, 메시지)는 DB에 있지만 사용자가 읽는 일기로 묶는 접점이 없다 |

## 결론

프로파일링은 별도 기능이 아니라 목표 모델의 한 사용법이다. "알아낸다"를 목표로 두면 질문·재촉·포기·늦은 답 처리가 시키는 일과 같은 장치로 돈다. 일기는 이 위에 얹을 수 있는 활용 예시일 뿐 이번 범위가 아니다.

## 발견한 것

| # | 내용 | 처리 |
|---|---|---|
| J1 | 오늘 끝난 목표가 턴 입력에서 빠져, 방금 알아낸 사실을 다음 흐름이 모름. 할 일 시나리오에도 똑같이 해당 | 설계 반영: 턴 입력에 현재 계획일에 종료된 목표(결과·사유) 포함(§5.1) |
| J2 | 관련 목표가 없는 메시지를 무시하면 어디에도 남지 않음 | 해결. 흐름 밖 메시지는 다음 흐름이 열릴 때 전부 그 흐름으로 옮겨지고(설계 §8.5), 그 흐름의 정리 호출이 "(무시됨)" 표시와 함께 본다(§5.3) |
| J3 | 사용자가 읽는 기록 산출물이 없음 | 활용 예시라 범위 밖 |
| J4 | 묻기 목표도 `goal_max_active`를 차지 | 상한 기본값 결정 시 고려(§7) |

## 확인된 것

- 질문을 목표로 두면 완료 조건·재촉·포기가 시키는 일과 같은 장치로 돈다. 별도 모델이 필요 없다.
- 활성 목표의 진행 메모가 흐름 사이 문맥을 이어준다(12:30 회의 질문).
- 늦은 답은 활성 목표 덕에 무엇에 대한 답인지 알아본다(21:10).
