# v4 이용 시나리오 2: 조급하고 시킬 일 많은 Agent

첫 시나리오(`harness-scenario-v4.md`)가 평범한 하루였다면, 이번에는 상위 프롬프트와 턴 규칙이 공격적인 경우다. 상한·타이밍·비용 쪽 허점을 찾는 게 목적이다.

## 설정

| 항목 | 값 |
|---|---|
| 방침 | `health`(물 2시간마다, 스트레칭), `work`(오전 지시, 보고), `study`(영어 단어 20개), `chores`(설거지, 빨래), `sleep`(23시 취침) |
| 프롬프트 성향 | 이어가기 1–3분 간격, 강한 압박, 목표를 잘게 많이 만듦, 흐름을 짧게 끊고 바로 다음 개입 |
| 상한(예시) | `goal_max_active`=5, `open_max_pending`=6, `min_lead`=60초, 디바운스 20초, `daily_call_limit`=150 |
| 블랙아웃 | 01:00–08:00 |

### 09:00 개시 턴 중 사용자 메시지

| 시각 | 사건 | 루프 | 결과 |
|---|---|---|---|
| 09:00:00 | `R1`(work) 발화 | 개시. 2 읽기 → 3 LLM 호출 시작. 흐름은 커밋 tx에서 생긴다(H6과 같은 원칙) | |
| 09:00:10 | 사용자 "아 오늘 오전 회의 있어" | 흐름이 아직 없음 → 흐름 밖 `pending`으로 기록 | |
| 09:00:15 | 커밋: `F1` 생성, G1–G3 생성, "회의 전에 메일 3개 처리해" 전송, `continue 09:01:15` | **허점 P1**: 09:00:10 메시지는 흐름 밖 `pending`이다. 흐름이 열려 있는 동안 루프는 "그 흐름 것만" 고르므로, 이 메시지는 흐름이 닫힐 때까지 판정도 응답도 안 된다. AI는 회의 얘기를 못 듣고 계속 재촉한다 | |

같은 문제의 반대편: 턴이 `end`로 흐름을 닫는 동안 io 중에 온 흐름 내 메시지는 미응답으로 흐름에 남은 채 흐름이 닫힌다. v3는 `close_flow`가 미응답을 인바운드로 옮겼는데, v4 문서에는 이 단계가 없다.

## 발견한 허점

| # | 허점 | 제안 |
|---|---|---|
| P1 | 흐름 경계와 메시지가 엇갈림. (a) 개시 턴 io 중 온 메시지가 흐름 밖에 남아 흐름이 닫힐 때까지 방치된다. (b) 닫는 턴 io 중 온 흐름 내 메시지가 미응답인 채 흐름과 함께 닫힌다 | (a) 흐름을 여는 커밋 tx가 그 시점의 흐름 밖 `pending` 메시지를 전부 흐름으로 옮긴다(미응답이 되어 디바운스 턴이 답함). (b) 흐름을 닫는 tx가 미응답을 흐름 밖 `pending`으로 옮긴다(v3 `close_flow` 4단계). 이러면 "흐름이 열려 있으면 모든 사용자 메시지는 흐름 안"이 불변식이 된다 |
| P2 | I3 보정 예약이 I6 상한에 막힘 | 하네스 보정 예약은 `open_max_pending`에서 제외. 보정 수는 활성 목표 수로 이미 묶여 있다 |
| P3 | 디바운스 대기 중 이어가기 발화가 반쪽 입력에 답함 | 이어가기 발화 시 디바운스가 걸려 있으면 디바운스 만료까지 미룬다. 그 턴 하나가 둘 다 처리한다 |
| P4 | 빈 흐름(사용자 메시지 0개, AI 메시지 0개)도 정리 호출 | 주고받은 메시지가 없는 흐름은 정리 `skipped` |
| P7 | 계획 출력이 상한을 넘을 때 규칙 없음 | `at`이 이른 순으로 상한까지 저장, 나머지 버림 + 로그. 턴의 `open_reserve`는 지금처럼 도구 거부 |
| P8 | H5(과거 시각은 `now`로)가 v3 클램프 `now+min_lead`와 어긋남 | 개시 예약 저장은 v3 클램프 그대로: `clamp(now+min_lead, now+max_lead)`, 블랙아웃이면 끝으로. H5는 이 규칙에 포함된다 |

## 결정 필요

| # | 질문 | 선택지 |
|---|---|---|
| D1 | AI가 연 흐름이 연달아 올 때 간격을 둘까 | (가) 프롬프트에 맡김. 밀린 목록이 보이니 AI가 합칠 수 있다 (나) 하네스 최소 간격 `open_min_gap`: AI 개시 흐름이 닫힌 뒤 N분 안에는 다음 AI 개시를 미룬다. 사용자 개시는 예외 |
| D2 | 일일 상한에 걸렸을 때 사용자 메시지도 막을까 | (가) v3처럼 전부 보류 (나) 상한을 AI 개시용과 사용자 응답용으로 나눠, AI 개시만 먼저 막힌다 |
